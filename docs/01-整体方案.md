# 01 整体方案
> 自制 LLM 项目的总体设计；各阶段细节以对应的专题文档为准（见 AGENTS.md 文档地图）。

# 目标定位
教学向：走通 预训练 → SFT → DPO 全流程，亲手验证各环节原理，不追求 SOTA。

# 关键决策
| 项 | 决策 |
|---|---|
| 模型架构 | Llama 结构（RMSNorm + SwiGLU + RoPE，decoder-only） |
| 参数规模 | ~100M |
| 语料语言 | 中文，几亿 token |
| 对齐方案 | DPO（不做 RLHF） |
| 评测 | 纳入步骤（见下文） |
| 交付 | 训练代码 + 评测 + 简单推理脚本 |

# 开发/训练环境
- 日常开发：Mac M2（PyTorch MPS 验证小实验）
- 正式训练：Windows + RTX 5080（CUDA），代码需跨平台可跑

# 实施步骤
1. **语料准备**：选中文开源语料，清洗/去重/过滤，得到预训练文本
2. **Tokenizer**：训练 BPE 分词器（词表 ~32k）
3. **模型实现**：Llama 结构，~100M 参数
4. **预训练**：next-token 预测，关注 loss 曲线与困惑度
5. **SFT**：中文 QA 数据，loss 只算回答部分（mask 问题）
6. **DPO**：构造偏好对（chosen/rejected），直接偏好优化
7. **评测**：
   - 预训练：loss 曲线 + 困惑度
   - SFT/DPO：人工抽查 case 对比微调前后输出；有余力跑 MMLU/C-Eval 子集
8. **推理脚本**：加载权重，命令行交互式对话

# 模块划分
拆成 7 个模块，可分配给不同人并行开发；模块间只通过输入/输出契约对接，不看彼此内部实现。

| # | 模块 | 输入（契约） | 输出（契约） |
|---|---|---|---|
| 1 | 语料处理 | 中文开源语料源 | `corpus.txt`：清洗后的纯文本（一行一段） |
| 2 | Tokenizer | `corpus.txt` | `tokenizer/`：BPE 模型文件 + `encode/decode` 接口 |
| 3 | 模型定义 | 超参配置（层数/维度等） | `model.py`：标准 `forward(input_ids) → logits` |
| 4 | 预训练 | `corpus.txt` + tokenizer + model | `pretrain.ckpt` + loss 曲线日志 |
| 5 | SFT | ckpt + `sft.jsonl`（Q/A 对） | `sft.ckpt` |
| 6 | DPO | sft.ckpt + `dpo.jsonl`（chosen/rejected 对） | `dpo.ckpt` |
| 7 | 评测与推理 | 任意 ckpt + tokenizer | 困惑度报告、case 对比表、命令行对话脚本 |

## 对接约定
- **统一数据契约**：文本用 `.txt`、数据集用 `.jsonl`、权重用 `.ckpt`；字段 schema 写入各专题文档，只认文件不认人
- **并行关系**：模块 1→2→3 可并行（tokenizer 只需语料样本，模型定义不依赖数据）；4→5→6 串行但解耦（下游只依赖上游 ckpt + tokenizer）；模块 7 全程并行（用随机初始化 ckpt 即可先行开发）
- **完成标准**：每个模块配 README + 冒烟测试，验证输出符合契约即视为完成
