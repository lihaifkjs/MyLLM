# 设计决策（已与项目 owner 对齐 2026-10-05）
| 决策点 | 结论 |
|---|---|
| 客观题基准 | **C-Eval**（中文，贴合教学向中文模型；不跑 MMLU） |

# 1. 困惑度评测 `src/eval/ppl.py`
- 统一入口：对任意 ckpt 在同一评测语料上算 ppl，解决"train 日志里 val_ppl 分散在各 jsonl、无法横向对比"的问题
- **评测语料（两源，按 ckpt 类型自动选择，可用 `--source` 强制）**：
  - pretrain ckpt：`data/clean/tokens.bin` 的**末尾 200k token** 切片（训练用 1 epoch，尾部大概率被见过——教学向可接受，跨 ckpt 可对比是首要的）
  - sft/dpo ckpt：`data/sft_val.jsonl` 的回答字段拼成文本（与 SFT 监督区间一致，更贴近下游任务）
- 算法：teacher forcing，`ppl = exp( 总 NLL / token 数 )`， batch 前向、右 pad、padding 不计入 NLL（复用 mask 思路）
- 输出：屏幕打印 + 追加 `logs/ppl_report.jsonl`（ckpt / source / ppl / n_tokens / 时间），多 ckpt 多次运行自动累积成报告
- 用法：`python -m src.eval.ppl --ckpt checkpoints/dpo.ckpt`（默认按文件名推断 source）

# 2. C-Eval 子集评测 `src/eval/ceval.py`
- **数据源**：HuggingFace `ceval/ceval-exam`（parquet，需 pyarrow——docs/07 已加入 requirements）；下载走 `HF_ENDPOINT`（Windows 本机需 `https://hf-mirror.com`）
- **子集**：只用 **val split**（各科目答案公开；test split 答案不公开，dev split 仅 5 题/科作 few-shot 示例）→ 全量约 1346 题，**随机采 800 题**（seed=42，`--num-questions` 可调）
- **prompt 格式（0-shot）**：
  ```
  以下是中国关于{科目}的考试题目。请选出正确答案。
  {question}
  A. {opt_a}
  B. {opt_b}
  C. {opt_c}
  D. {opt_d}
  答案：
  ```
  以 `<bos>` 开头，科目用 C-Eval 的 subject_name（中文）
- **打分**：一次前向，取末位 logits 中 "A"/"B"/"C"/"D" 四个候选 token 的 logprob，argmax 为预测（**比较 logprob 而非生成**，免了解码随机性，是小模型选择题评测的通行做法）
- 注意：依赖 tokenizer 把 "A"~"D" 编为单 token（byte_fallback 词表应满足）；实现时校验并显式报错
- 输出：屏幕打印总准确率 + 按学科 accuracy 前 10/后 5，追加 `logs/ceval_report.jsonl`
- 预期：100M 模型得分低（可能接近 25% 随机线），教学意义在跑通流程

# 3. Case 对比 `src/eval/case_compare.py`
- 内置 **12 个固定问题**（初版，覆盖：事实问答/常识推理/开放生成/已暴露复读的问题如"中国的首都是哪里"），可 `--questions-file` 覆盖
- 同一问题分别用 `sft.ckpt` / `dpo.ckpt` 生成（**同一套解码参数**，默认带复读缓解：temperature=0.7、top_p=0.9、no_repeat_ngram=3，参数可传）
- 输出：`logs/case_compare.md`（Markdown 表格：问题 | SFT 输出 | DPO 输出），人工抽查载体

# 4. 对话推理 `src/chat/chat.py`
- 命令行交互：`python -m src.chat.chat --ckpt checkpoints/dpo.ckpt`（默认 dpo.ckpt），REPL 循环
- **多轮**：历史按模板拼接 `<bos>用户：{q1}\n助手：{a1}<eos>用户：{q2}\n助手：…`，超 ctx1024 时从最早一轮开始丢弃（决策 4）
- **解码策略（复读缓解核心）**：
  | 参数 | 默认 | 说明 |
  |---|---|---|
  | `--greedy` | 关 | 贪心开关（对照用） |
  | temperature | 0.7 | `--temperature` |
  | top_p | 0.9 | `--top-p` |
  | repetition_penalty | 1.1 | 对已出现 token 的 logits 惩罚 |
  | no_repeat_ngram | 3 | 生成中禁用的重复 n-gram 大小 |
  | max_new_tokens | 200 | 生成上限 |
- 复读缓解的效果通过 case_compare 与 §6 的"复读检测"量化（简单启发式：输出中出现 3 次以上重复子串即记 1 次复读，report 里给出复读率）

# 文件结构
- `src/eval/ppl.py`：统一 ppl 入口（双评测源 + 报告累积）
- `src/eval/ceval.py`：C-Eval 下载/采样/评分/报告
- `src/eval/case_compare.py`：固定问题集 sft vs dpo 对照表
- `src/eval/questions.py`：内置 12 题（独立成文件便于 owner 增删）
- `src/chat/chat.py`：REPL 多轮对话 + 解码策略
- `src/chat/decoding.py`：解码函数（greedy/sampling/repetition_penalty/no_repeat_ngram），供 chat 与 case_compare 共用
- `tests/test_eval.py`：冒烟测试

- 冒烟测试（2026-10-05，CPU）：`tests/test_eval.py` 9 项全过；全量 `tests/` 39 passed
- **ppl 实测（2026-10-05，Windows/4070 Ti，CUDA）**（`logs/ppl_report.jsonl`）：

  |---|---|---|---|
  | pretrain.ckpt | tokens.bin 尾部 | 199,680 | 59.78 |

- **case_compare 实测（2026-10-05）**：`logs/case_compare.md` 生成正常；采样解码（temp=0.7）+ 复读缓解下 **SFT/DPO 复读率均为 0/12**，机械复读被解码策略消除；输出内容仍肤浅/事实错误（100M 基座固有短板，与 docs/06/07 结论一致）
- **chat.py 实测（2026-10-05）**：管道输入跑通 REPL（提问→生成→`/exit` 退出），多轮拼接与解码参数生效
