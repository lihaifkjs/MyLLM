# 02 语料处理
> 模块 1 的专题文档；总体背景见 `docs/01-整体方案.md`。
> 契约：输入中文开源语料源 → 输出 `data/corpus.txt`（清洗后纯文本，一行一段）。

# 语料选型
| 项 | 决策 |
|---|---|
| 主语料 | Skywork/SkyPile-150B（HuggingFace: `Skywork/SkyPile-150B`，分片在 `data/` 下，单片约 1.1GB） |
| 备选/补充 | 万卷1.0（nlp 部分）、WuDaoCorpora |
| 原始量级 | 约 5GB（采样），清洗后目标 2–3 亿 token |
| 原始格式 | JSONL，每行一个文档，正文在 `text` 字段（WuDao 为 `content`） |

选 Skypile-150B 的理由：中文、已过滤黄暴低质内容、单文档平均 1000+ 字、JSONL 易解析、可只下载部分文件采样。

# 处理流程
4 步管道，每步独立脚本，可断点续跑：

1. **下载采样** `src/corpus/download.py`
   - 下载源：hf-mirror 镜像 resolve 直链（`https://hf-mirror.com/datasets/<repo>/resolve/main/<分片>`），直接 HTTP 下载，不依赖 huggingface_hub
   - 断点续传：分片内 `.part` + Range 头续传；分片级进度记录（`data/raw/download_state.json`），单分片失败重试 3 次（指数退避）
   - 从 HuggingFace 拉取 SkyPile-150B 部分分片，累计原始字节达 约 5GB 即停
   - 统一抽取正文字段，转存 `data/raw/sample.jsonl`（字段：`{"text": ...}`）
2. **规则清洗** `src/corpus/clean.py` → `data/clean/cleaned.jsonl`
   - 去 HTML 标签、URL、邮箱
   - 规范化不可见字符/全半角空白/连续空行
   - 按标点（。！？\n 等）拆段，段即输出行
   - 长度过滤：段长 <50 或 >10000 字符丢弃
   - 中文字符占比 <30% 的段丢弃
3. **去重** `src/corpus/dedup.py` → `data/clean/deduped.jsonl`
   - 段级精确去重（哈希集合）
   - 段级 MinHash 近似去重（`datasketch`，Jaccard 阈值 0.8，64 排列）
   - 性能：签名计算 multiprocessing 多核并行，主进程判重+流式写盘，带进度日志
4. **汇总输出** `src/corpus/build.py` → `data/corpus.txt`
   - 一行一段，UTF-8
   - 输出统计报告：行数、总字符数、token 估算量（中文字符 ≈ token 上界粗估）、各规则丢弃量

# 目录结构
```
data/
  raw/            # 原始采样（.gitignore）
  clean/          # 中间产物（.gitignore）
  corpus.txt      # 最终契约输出（.gitignore）
src/corpus/
  download.py  clean.py  dedup.py  build.py
```

# 依赖
- `datasketch`（MinHash）、`httpx`（下载）、标准库为主
- 依赖清单维护在 `requirements.txt`

# 完成标准
- `data/corpus.txt` 符合契约：UTF-8、一行一段、无 HTML/URL 残留（抽检）
- 规模达标：粗估 ≥2 亿 token
- 冒烟测试：用小样本（约 1000 文档）跑通 4 步管道，输出统计报告无异常
